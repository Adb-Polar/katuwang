## 1. Executive Summary

**Katuwang** (Tagalog for *"helper"* or *"partner"*) is a web-based peer
tutoring and academic mentoring platform for Junior and Senior High School
students (Grades 7–12), built as an undergraduate capstone project (Bicol
University, BS Information Technology) for **Taysan Resettlement Integrated
School (TRIS)**.

### Core Objectives

1. **Student Privacy by Design:** Sequential anonymous identities (`STU-XXXX`
   for learners, `TUT-XXXX` for tutors) so peers never see each other's real
   name, email, or contact info, in line with the Data Privacy Act of 2012
   (RA 10173).
2. **Competency-Based Quality Assurance:** Tutors must pass a topic
   assessment before they can create classes on that topic.
3. **Structured Peer Tutoring:** 1-on-1 and small-group classes with
   per-session scheduling, conflict detection, enrollment tracking, and
   capacity management.
4. **Multi-Tiered Role Governance:** Three roles — Student Learner, Student
   Tutor, Administrator — each with a dedicated portal and route-level access
   control.

## 2. Architecture & Technology Stack

Full-stack monolith on the Next.js App Router: Server Components fetch data,
Client Components (`"use client"`) handle interactive forms/modals, Route
Handlers under `src/app/api/**` are the backend, and `src/proxy.ts`
(NextAuth middleware) enforces RBAC at the network edge before any protected
page or route runs.

```
Browser (React 19 + Tailwind 4/DaisyUI 5, OKLCH theme)
        │  HTTPS + NextAuth session cookie
        ▼
Next.js App Router (Node.js)
  ├─ src/proxy.ts            — RBAC middleware, redirects to /unauthorized
  ├─ src/app/api/**/route.ts — Route Handlers (REST-style JSON endpoints)
  ├─ src/lib/auth.ts         — NextAuth credentials provider, JWT session
  ├─ src/lib/validations/**  — Zod schemas at every request boundary
  └─ src/lib/prisma.ts       — singleton Prisma client
        │
        ▼
MariaDB / MySQL  (via @prisma/adapter-mariadb)
```

## 3. Identity, Authentication & Security

- **Credentials provider** (`src/lib/auth.ts`, NextAuth): email + bcrypt
  password hash, JWT session strategy, 8-hour session `maxAge`.
- **JWT/session payload:** `id`, `anonymousId`, `role`, `firstName`,
  `lastName`, re-checked against the DB mid-session so a status/role change
  takes effect without waiting for token expiry.
- **Account gates:** `AccountStatus` (`ACTIVE`/`SUSPENDED`/`BANNED`/`PENDING`/
  `DECLINED`), an optional admin-toggled registration-approval gate
  (`requireRegistrationApproval`), and an optional email-verification gate
  (`requireEmailVerification`) — see `docs/reference/decisions.md` for the
  precedence between them.
- **Password reset & change:** `/forgot-password` → `/reset-password`
  (hashed, expiring, single-use `PasswordResetToken`, emailed via
  `src/lib/mail.ts`/Nodemailer, console-logged fallback if SMTP is unset);
  self-service change-password on every role's profile/settings page.
- **Route protection:** `src/proxy.ts` middleware guards `/admin/*`,
  `/tutor/*`, `/learner/*`, `/dashboard/*`; every API route additionally
  re-checks `getServerSession` + role server-side.
- **Hardening:** login rate-limiting, generic auth error messages with a
  dummy bcrypt compare (no user-enumeration timing signal), a 72-byte
  password cap, and security headers in `next.config.ts`.
- **Double-blind anonymity:** peer-facing queries select only `id` /
  `anonymousId`; real names/contact info never cross the learner↔tutor
  boundary (an admin-only `showTutorRealNames` override exists).

## 4. Core Feature Areas

Each area below is complete; see `docs/reference/feature-checklist.md` for
the itemized, actively-maintained status table.

- **Registration & onboarding** — separate learner/tutor flows
  (`/register/learner`, `/register/tutor`), Zod-validated, atomic anonymous
  ID allocation (`src/lib/idGenerator.ts`, `IdCounter` table, race-safe via
  `increment: 1`), optional admin approval queue.
- **Class scheduling & management** — `TutorClass` as a multi-session course
  container (`ClassSession` per meeting, `ClassTopic` per sub-topic),
  capacity/overlap checks, publish/unpublish, moderation (suspend/ban/appeal)
  from `/admin/classes`.
- **Learner enrollment** — browse, enroll, unenroll (`ClassEnrollment`),
  full history retained across class status changes.
- **Tutor matching** — weighted `rankMatches()` scoring (subject/topic
  overlap, grade proximity, schedule fit), a fallback `TopicRequest` flow
  (public or tutor-directed) that a tutor can accept to auto-create a class,
  and a learner-facing tutor browser.
- **Assessment** — tutor topic-certification quiz (admin-authored question
  bank, platform-wide pass-percent/question-count config) plus a distinct
  per-`ClassSession` learner pre-/post-test (`SessionTest*`) with pre→post
  score-gain reporting.
- **Chatbot Assistant** — deterministic, no-LLM intent + FAQ matcher
  (`src/lib/chatbot/`), per-portal widget, admin review of unmatched queries
  at `/admin/chatbot`. See `docs/reference/chatbot.md`.
- **Notifications** — DB-backed, per-user, covering registration, class,
  certification, request, appeal, and report events; bell dropdown in every
  portal layout.
- **Moderation & trust/safety** — account suspend/ban (`/admin/users`), class
  suspend/ban + tutor appeals (`/admin/class-appeals`), learner-filed abuse
  reports on a tutor or class (`/admin/abuse-reports`), and an admin audit
  log (`/admin/audit-log`) of moderation actions.
- **Analytics** — descriptive-only reports (users, classes, certifications,
  30-day enrollment trend) at `/admin/reports`.
- **Global search** — role-scoped quick search (classes/tutors/topics)
  in every portal top bar.

## 5. Database

The schema is managed entirely by Prisma (`prisma/schema.prisma`, MySQL/
MariaDB). It is not reproduced here — `prisma/schema.prisma` is the source of
truth, and `docs/reference/erd.md` is its auto-generated, always-current
rendering (regenerated by `npx prisma generate`, never hand-edited).

Model groups, for orientation:

- **Identity & auth:** `User`, `TutorProfile`, `PasswordResetToken`,
  `VerificationToken`
- **Taxonomy:** `Subject`, `Topic` (admin-editable; there is no `SubjectArea`
  enum — subjects/topics moved to these tables 2026-09-04)
- **Classes & sessions:** `TutorClass`, `ClassTopic`, `ClassSession`,
  `ClassEnrollment`, `ClassAppeal`
- **Matching:** `TopicRequest`, `TopicRequestTopic`, `TopicRequestSlot`,
  `ClassRecommendation`
- **Assessment:** `TopicCertification`, `AssessmentQuestion`,
  `AssessmentOption`, `AssessmentAttempt`, `AssessmentAttemptItem`,
  `QuestionRequest`, `SessionTest`, `SessionTestQuestion`,
  `SessionTestAttempt`, `SessionTestAttemptItem`
- **Trust & safety:** `Report`, `ReportViolation`, `AuditLog`
- **Platform:** `IdCounter`, `PlatformSetting`, `Notification`, `ChatbotMiss`
