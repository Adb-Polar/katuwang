Open items
 - Admin topic/subject management page (add/edit topics & subjects) —
   subjects/topics are currently hardcoded in src/lib/subjectTopics.ts.
   Making them admin-editable means moving them into the DB. FULL PLAN written:

   chose the full scope; execution deferred to a dedicated effort.

 - Admin bulk import for the assessment question bank — today the only way to
   add questions is QuestionFormModal in QuestionBankManager.tsx, one at a
   time. A topic isn't assessable until it has minBankSize (default 5) active
   questions (TopicAssessmentConfig), so real content entry needs a batch
   path. NO schema change: reuses AssessmentQuestion + AssessmentOption as-is;
   at most add an AUDIT_ACTIONS.QUESTIONS_IMPORTED constant (a TS const, not a
   migration).
   Suggested shape:
     * New POST /api/admin/assessment-questions/bulk — ADMIN-only, reuses
       createAssessmentQuestionSchema (src/lib/validations/assessment.ts) per
       row inside one prisma.$transaction, keeps the existing
       SUBJECT_TOPICS[subject].includes(topic) check, writes one summary audit
       row.
     * New "Import" modal in QuestionBankManager (Questions tab): paste input
       -> client-side preview table (row #, prompt, subject.topic, valid/error
       + first message) -> "Import N valid" button.
   Open design questions (raised with the owner, not yet decided):
     * Input format — paste JSON (best fit: every write path here is already
       JSON + Zod, no new dependency, no first-ever file input) vs CSV upload
       (needs a CSV parser dependency + a file input, and a fixed wide column
       layout to carry 2-6 options).
     * Subject/topic per row — inherit from the Questions-tab selectors with a
       per-row override, vs require subject+topic on every row, vs pick one
       subject+topic in the import dialog for the whole batch.
     * Invalid rows — preview then import only the valid rows and report what
       was skipped, vs all-or-nothing (reject the whole batch if any row
       fails).
     * Batch size cap (e.g. 200 questions per request).
