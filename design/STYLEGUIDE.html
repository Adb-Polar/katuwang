Katuwang · production baseline · frozen 2026-09-01

The key

Katuwang replaces names with a notation — STU-XXXX, TUT-XXXX, plus grade, section, and status. The interface is the key to that notation: calm, symmetric where the screen allows, delimited by hairlines like a printed legend. Colour tells you which side of the double-blind a token belongs to, so a real name is never needed.

Governing files: design/ROUND-2-CONTEXT.md · design/PRODUCTION-BASELINE.md · design/round-2/base.css. Locked Round 1 study: design/round-1/E.html.

1 · Source boundary

Where the form came from

Allowed evidence: the name Katuwang (Tagalog: helper / partner); Philippine K-12, Grades 7–12; double-blind anonymity under RA 10173; the sequential IDs STU-XXXX / TUT-XXXX; peer tutoring; three roles; the Filipino section as a named cohort; weekly recurring session windows; topic assessment; admin moderation and audit trail; students on phones.

Prohibited influence: SaaS/admin dashboard aesthetics, edtech products, Material / Meta house styles, design galleries and UI kits, DaisyUI's default look, browsing type catalogues for a look. The premise came from the notation system itself, not from any existing interface.

Signature relationship: colour = which side of the double-blind a token is on. Identities stay hidden because the colour already tells the interface everything it needs.

2 · Typography

Two faces, two jobs

Fragment Mono — Wei Huang, SIL OFL 1.1 — is notation: IDs, dates, times, counts, capacity, status codes, navigation items, audit strings, code fields, buttons.

Apfel Grotezk — Collletttivo / Alexander Meyer, SIL OFL 1.1 — is speech: page titles, section labels, sentences, descriptions, form labels.

notation — Fragment Mono

STU-2071 · TUT-0148 · Tue 4:00–5:30 PM · 4 / 6 · 28 Aug 2026

speech — Apfel Grotezk

Learn with a peer who gets it.

Small-group practice on setting up and solving first-degree equations.

Scale & weight

  • Weights: 400 / 500 / 700 only. Low contrast — hierarchy comes from size, colour role, and space.
  • Page title clamp(1.6rem, 4vw, 2.1rem), weight 500. Section label = Fragment Mono .72rem, .18em tracking, uppercase, system grey.
  • Body 1rem / 1.55. Notation blocks get generous line-height (1.9–2.15) so each line reads as its own legend entry.
  • Measures in ch / rem. Prose capped ~60ch; centred text ≤ 60ch or it left-aligns.
  • Fragment Mono never sets long body prose. Apfel Grotezk never sets an ID, time, count, or status.
3 · Colour — identity + state

Two colour families

Canvas is warm near-white oklch(98% 0.004 90). Colour does two jobs, kept separate. Identity colours say which side of the double-blind a token is on — only ever on IDs and identity-linked labels. State colours use conventional semantics (blue / green / amber / red) for lifecycle and feedback. (Colour rules reopened 2026-09-01 for usability; typography and layout stay locked.)

Identity — who

Aa Ink — neutral oklch(22% 0.01 70) Headings, neutral prose and data, primary buttons.
Aa Learner — violet oklch(45% 0.15 300) Only STU-XXXX + learner-portal accent.
Aa Tutor — gold oklch(48% 0.12 88) Only TUT-XXXX + tutor-portal accent.
Aa System — grey oklch(48% 0.014 265) Muted meta, disabled, archived (Completed, Draft), admin-portal accent.

State — what is happening

Aa Info — blue oklch(52% 0.13 245) Informational notes, Scheduled.
Aa Success — green oklch(50% 0.13 150) Open, Active, Enrolled, Published, verified topics, confirmations.
Aa Warning — amber oklch(60% 0.13 65) Pending, Full, needs-attention banners.
Aa Error — red oklch(53% 0.21 25) Suspended, Cancelled, validation errors, destructive actions, moderation notices.

Colour still never stands alone

Every colour is paired with a redundant non-colour cue so the interface survives greyscale and colour-blindness:

  • IDs carry the STU- / TUT- prefix.
  • Status = a 3-letter Fragment Mono code and the full word.
  • Verified topics carry a leading ✓.
  • Alerts carry a leading glyph (i ✓ ! !) + a bold lead word.
  • Errors: red + leading ! + heavier weight + position.

Keep the two families apart

  • Identity colour never marks a state; state colour never marks a person.
  • An STU-XXXX stays violet even in a red SUS Suspended row — the ID and the status chip carry different colours on purpose.
  • Tutor gold hue sits at 88 to stay clear of amber (65).
  • No fifth state hue. New states reuse info / success / warning / error / neutral.

Portal accent mapping

  • Learner portal → learner violet (nav active state, focus ring, portal label).
  • Tutor portal → tutor gold.
  • Admin portal → system grey / ink (admin belongs to neither peer).

5 · Composition

A legend, not a set of cards

  • No boxed cards, no drop shadows. A group is a single top hairline (1px, ink at 16%) + a Fragment Mono uppercase label + content flowing beneath.
  • Rules are only ever thin horizontal separators — section tops, table rows, list rows. Never a full border/outline around content.
  • Fills appear only on: primary buttons (ink fill, canvas text), status chips (role tint ~10–13%), selected form options.
  • Radius 2px everywhere. No pills.
  • Portal layout: a left vertical nav (Fragment Mono list — the index to the key) + a centred content column, max-width ~64rem.
  • Marketing & auth are fully centred / symmetric. Data tables left-align but keep the colour roles.
  • Mobile: the nav collapses to a native <details>/<summary> disclosure (no JS). Tables reflow to stacked label/value rows via explicit markup labels.

8 · Accessibility & recoverability — fixed boundaries

Non-negotiable

  • Visible focus on every interactive element: 2px solid outline in the portal accent, outline-offset 2–3px. Never removed.
  • Semantic HTML first — real <button>, <a>, <table>, <details>, <label>. ARIA only where native elements cannot express the behaviour.
  • Every colour-coded item also carries a text or code cue (§3). Verify greyscale and colour-blind rendering.
  • Contrast target 4.5:1 for body text at shipped sizes; re-check every state colour (--info · --success · --warning · --error) and --tutor at the smallest sizes and tune the token, not the role.
  • Keyboard: nav disclosure, table row actions, and dialogs fully operable; a dialog traps focus while open and restores it on close.
  • Preserve user input across validation errors, network failures, accidental dismissal, and navigation.
  • Respect prefers-reduced-motion; any motion ≤ 150ms opacity/transform.
  • Wide content (tables, code) scrolls inside its own container; the page body never scrolls sideways.
9 · Invariants & allowed variation

What is fixed, what can move

Allowed variation

  • Portal-specific lead / nav-active colour.
  • Left-aligned dense layouts (keeping identity + state roles intact).
  • New status codes reusing an existing state tint (info / success / warning / error / neutral).
  • Tuning any colour token's lightness/chroma for contrast.
  • Content density, row counts, filter counts per screen.

Prohibited normalisation

  • A new state hue beyond info / success / warning / error.
  • Mixing the families — identity colour on a state, or a state colour on a person.
  • Card chrome, pills, boxes/borders around content, shadows.
  • An icon set replacing the code + word cue.
  • Apfel Grotezk on IDs/times/status; Fragment Mono on long prose.
  • Centring forced onto data tables.

Reopening conditions. Reopen the locked direction only for new subject evidence, cultural harm, an accessibility failure unsolvable within these rules, a changed product requirement, or an explicit user override. Record the reason and the authorising decision in PRODUCTION-BASELINE.md.
